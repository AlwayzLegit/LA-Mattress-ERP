# Performance and QA pass — 2026-10-18

Local run of `main` at `0906661` (PR #225) on a Windows 11 workstation (Ryzen 9 7950X3D,
256 GB), Node 24.12, pnpm 9.15.9, Postgres 16 and Redis 7 in Docker. The web app was measured
as a **production build** (`next build && next start`) talking to the API through the same
`/v1` proxy production uses; the API ran from `nest start --watch` (compiled JS, same code
path as production). All numbers below are local: no network between browser, web and API,
and a Postgres on the same machine. Production adds roughly 100–300 ms per round trip between
Vercel (web) and Render (API), so every _serial_ request counted here costs more there.

Raw outputs: `docs/perf/raw/`. Scripts: `docs/perf/scripts/`. Browser QA log:
`docs/perf/2026-10-18-qa-notes.md`.

Two things that bit on this machine and would bite any new developer:

- **Node 24 cannot boot the API on `main`**: `@sentry/profiling-node` has no prebuilt binary
  for it and the unconditional import throws at startup even with `SENTRY_DSN` unset → PR #227.
- **The integration specs cannot run natively on Windows**: they `execFileSync('pnpm', …)` to
  reset their database, and Node cannot spawn the `pnpm.cmd` shim without a shell. Running the
  suite in a `node:22` container (`docs/perf/scripts/run-specs-linux.sh`) works and matches CI.

## 6. Backlog — ranked

**Performance (next)**

1. **Bootstrap payload.** Fold `auth/me`, `members/me`, `locations`, `settings/pos`,
   `nav-counts`, `onboarding/checklist` into one `/v1/bootstrap` the shell fetches once;
   pages then start one RTT after the session probe instead of two. Biggest remaining win
   in production latency.
2. **Complete-sale as one request.** The register posts order → payments → complete serially;
   a single `POST /v1/orders/complete-sale` (or server-side chaining) removes two RTTs from
   the most frequent action in the store.
3. **Polling.** `/v1/inbox` every 30 s and on every navigation, `nav-counts` every 60 s, on
   every open tab. Pause when `document.visibilityState !== 'visible'`; consider one
   `/v1/shell/ticks` endpoint.
4. **Layout shift.** Reserve height for the deliveries board (`.db-grid` ≥ 60vh while loading)
   and the dashboard `.dh-grid` cards; CLS 0.73 / 0.16 today.
5. **Written-sales report.** 950 KB for a month of detail rows; paginate or stream the CSV
   path, and cap `includeAddress` rows.
6. **Pool size.** `DATABASE_POOL_MAX=10` with per-row fan-out elsewhere (`hydrateRun`,
   the order detail extras) — audit the other `Promise.all(rows.map(…))` sites the same way
   as #230.
7. **Import pipeline.** Products commit 15 ms/row, inventory 13 ms/row (row-by-row
   `import_rows` updates); fine for 2k rows, slow for the 24-month invoice history.

**Reliability and operations**

8. Sentry projects still do not exist for either app (`HANDOFF.md`, 2026-09-12 update); both DSNs unset in
   production. Without them none of the above regressions would be noticed.
9. Expose a build identifier (commit SHA) in the UI footer / `GET /health` — the browser
   audit asked for it and today findings cannot be pinned to a deploy.
10. CI runs each `*.int.spec.ts` against its own database in series (13.6 min in the
    container here); `pool: forks, singleFork: true` could be relaxed per-file with the
    per-spec databases already in place.
11. Developer onboarding: pin Node with `engines`/`.nvmrc` **enforced** (`engine-strict`),
    note the Windows limitation of the specs, add `docker-compose.override.yml.example`
    for machines where 5432/6379/3000 are taken.

**Security and housekeeping (from `HANDOFF.md`, still open)**

12. Rotate the shared owner password; create the manager/cashier identities so the
    security-override flow can be tested.
13. Stripe Billing go-live items (prices, webhook secret) — the API still activates plans
    without payment in stub mode.
14. `apps/web/public/sw.js` + the offline register: no test covered it this session; worth a
    Playwright run against the production build.
