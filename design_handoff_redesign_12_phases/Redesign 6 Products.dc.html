Phase 6 — Products, stock and cross-store visibility

Live prototype (Proto Products.dc.html). Drag a column header to move it; click to sort.
The user and the question

A salesperson with a customer asking "do you have it", and a warehouse lead deciding what to move. "Who has this, anywhere, right now?" The audit found the browser could only answer one location at a time. Now one row per SKU carries one column per store plus a company total, and a zero is a zero, not a missing row.

What we kept from the shipped browser

The owner asked for drag-to-reorder and click-to-sort columns; both survive with the location columns treated as ordinary columns (drag Glendale next to Product if that is how you read it; the order is remembered per browser). Advanced search stays a disclosure. The four-tab strip (Products · Stock by location · Counts · Receive) stays; Receive is built out below. The product page keeps every activity tab but leads with the location grid and ATP.

Design notes

Ive vs Forstall on the column count: Ive wanted six store columns collapsed to one "Company" number with a hover. Forstall: the question is where, and a hover is a click. Jobs: six numbers in a row read faster than one number and a tooltip; the store columns stay, tinted navy in the header so they read as one block.

Chaudhri on colour: a zero with open demand is red; a positive number below the store minimum is amber; a plain zero is grey. The footer says so in words — status never by colour alone.

Later: a Cost column for financial roles; a sticky first column when the table exceeds 1440.
